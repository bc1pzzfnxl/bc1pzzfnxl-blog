# Template vs deployment

`pzz-cms` is the **upstream template**. `bc1pzzfnxl-blog` is a **deployment** of
that template. The two repositories share most of their code, but not their
identity, their Cloudflare resources or their content.

Never copy a deployment-specific file back into the template.

## What is shared

These files are code, and changes flow from `pzz-cms` to the deployment:

- `src/**` (components, layouts, routes, content module, helpers, styles)
- `tests/**`, `scripts/**`, `migrations/**`
- `package.json`, `bun.lock`
- `astro.config.mjs` (it reads the site URL from `src/lib/site.ts`)
- `docs/**`, `README.md`, `AGENTS.md`, `CONTRIBUTING.md`, `SECURITY.md`, `PLAN.md`

## What belongs to the deployment

Never copy these from the template into a real site, or from a site into the
template:

| File | Why |
| --- | --- |
| `src/lib/site.ts` | Name, canonical URL, description, author, logo, default cover |
| `wrangler.jsonc` / `wrangler.deploy.jsonc` | Real D1 database id, R2 bucket, Worker name |
| `.dev.vars`, `.env*` | Secrets (`BETTER_AUTH_SECRET`, `SETUP_TOKEN`, owner email) |
| `public/favicon*`, `public/apple-touch-icon.png`, `public/images/*` | Branding and site assets |
| D1 rows and R2 objects | Articles, documents, categories, media |
| `content/` | The Git mirror of the deployment's articles; never committed in the template |
| `migration-output/` | Private imported content, gitignored |

`src/lib/site.ts` is the **single source** of the site URL: `astro.config.mjs`,
`robots.txt`, `llms.txt`, the sitemap, RSS and JSON-LD all read it. `public/`
must not contain a hardcoded `robots.txt` or `llms.txt`; those are generated by
`src/pages/robots.txt.ts` and `src/pages/llms.txt.ts`.

## Sync procedure

1. Make the change in `pzz-cms`, on a `feat/…`, `fix/…` or `chore/…` branch.
2. Run `bun run check` and `bun run build` there; let CI pass.
3. Copy only the shared files listed above into the deployment.
4. Check the deployment diff: it must not contain `site.ts`, Wrangler config,
   secrets, content or generated assets.
5. Run `bun run check` and `bun run build` in the deployment, push, let Workers
   Builds pass, then deploy.
6. Deploy with the local, gitignored `wrangler.deploy.jsonc`; never commit it.

## Content mirror

The deployment keeps a text mirror of D1 in `content/`:

```bash
bun run content:sync -- --config=wrangler.deploy.jsonc
bun run content:import -- --config=wrangler.deploy.jsonc
bun run media:gc -- --bucket=<r2-bucket> --config=wrangler.deploy.jsonc
```

- `content:sync` writes one `.mdx` per article plus `categories.json`,
  `media.json` and `manifest.json`. It mirrors **published** articles by
  default; `--all` includes drafts and must only be used with a private
  repository.
- `content:import` recompiles MDX and upserts the mirror into D1. It restores
  text and media metadata, not the R2 objects: images must still exist.
- `media:gc` deletes media rows and R2 objects that no current article or
  document references, after 7 days by default.
- The GitHub Action that runs `content:sync` is deployment-specific: it needs
  that deployment's Cloudflare secrets, so it lives in the deployment
  repository, not in the template.
- Images are never mirrored. Deleting a replaced image also breaks the old Git
  versions that referenced it; that is the accepted cost of staying inside the
  R2 free tier.

## Current gaps

- The deployment repository visibility is still under review; ADR 0004 expects
  a private blog repository.
- `src/lib/imageMeta.ts` and `src/components/ArticleImage.astro` are legacy from
  the Astro Markdown pipeline and are candidates for removal.
- The `shadcn` CLI is a dev dependency because the admin CSS imports
  `shadcn/tailwind.css`.
